# 主智能体改造：第一阶段验收说明

日期：2026-11-12  
状态：开发完成，待用户验收  
需求依据：`D:/Codex/outputs/主智能体改造方案-v0.4-待确认.md`

## 实现范围

1. 通用能力介绍：常见问法直接返回服务说明；其他能力问法由 Router 返回 `general=true`。不调用业务子 Agent、工具或 Composer，不展示业务卡片。含具体服务请求或风险表达的消息仍进入原有业务路由。
2. 编排：保留单个子 Agent 直接回复、多子 Agent 才调用 Composer；工具附件按子 Agent 分别收集，按执行计划顺序返回。
3. 用户表达：界面、状态提示、卡片、工具结果和新回复去除环境标签。读取老账户时清理既有资料和订单中的相关措辞，保留业务 ID、余额、交易状态、内部 `isDemo` 与聊天记录。
4. 匹配：先确认主题、日期、当天时段、咨询方式，每次最多问一个缺失项。用户一次给全即可搜索，关键条件来自推断时先确认。性别和预算由用户提出，换批时随其他条件一起传递。
5. 时间：工具要求 `date/timeStart/timeEnd/format`；只保留完全落在范围内的 Slot。单任务的匹配摘要、预约确认和卡片使用相同的 Slot 与上海时区格式，不由模型另外生成可约时间。无精确匹配时不展示条件外卡片。
6. 相关卡片：每个子 Agent 按业务操作挑选必要结果；目标预约或退款操作优先于辅助查询。同类查询保留当前结果。指定咨询师后，沿用当前有效候选的条件，只展示该咨询师的相应时段；多位候选而指代不唯一时先澄清。
7. 预约查询：当前预约默认只返回有效预约；包含取消记录需要用户明确询问历史或取消记录。完成、取消或改约只展示目标预约。
8. 卡片生命周期：保留最新回复才可操作的规则，服务端再次检查卡片是否有效、时段冲突和权益，历史卡片不能重复提交。

## 验收顺序

建议新建对话，避免旧回复中的既有文字影响观察。

| 输入或操作 | 预期 |
| --- | --- |
| 你现在能帮我做什么呢？ | 仅能力介绍，无子 Agent、工具和卡片 |
| 说说看，你都能帮我哪些忙呀 | 仅主路由和能力介绍，无业务执行 |
| 我想找一位合适的咨询师 | 询问缺失需求，不提前展示卡片 |
| 明天晚上线上聊工作压力，女咨询师，预算200元以内 | 直接搜索，卡片仅有符合条件的时段 |
| 我要约陈知宁这位咨询师 | 只显示该咨询师及原条件内时段，无历史取消预约 |
| 在卡片中确认预约 | 回复、卡片与选中的 Slot 完全一致，权益扣减一次 |
| 确认取消预约 加预约 ID | 只显示被取消的目标预约，释放一次权益 |
| 我现在有哪些预约？ | 不返回取消记录 |
| 查看以前的预约，包括取消记录 | 可返回取消记录 |
| 心理支持与订单查询同时提出 | 多个子 Agent 执行，Composer 合并，各任务保留必要卡片 |

## 阶段边界

本阶段的条件提取和是否需要追问仍由模型结合历史与 Prompt 判断；工具负责参数与 Slot 范围校验。完整 Matching State、动态上下文、Task Ledger 和记忆管理将在后续阶段实现。多意图的自然语言整合仍由 Composer 完成，卡片选择和业务事实由代码控制。

本阶段不新增心理支持状态、危机分级或人工通道。历史聊天原文继续保留，不批量改写历史回复。
